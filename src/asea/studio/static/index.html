What this is — in plain English

SILT moves a skill from one AI (the teacher) to another (the learner) — but only after it proves itself on test cases the teacher never saw. The skill is a packet of instructions (not weights), and you approve it by name. A skill that fails the gate is rejected, with reasons — nothing is faked, nothing silently degrades.

1 · Set up Skills · Suites · Transfer Add your teacher & learner models, pick a test (suite), and run a transfer to extract & gate the skill.
2 · Act on run Packets & Approval · Test · Train Approve / download the skill, check its accuracy, or (optional) train a real LoRA adapter & re-gate it.
3 · Probe Playground · Compress Ask a model a question live (base vs. with-skills), or compress + certify a model with SiltSpring.

About

The vocabulary, then the six honest steps (technical)

▾

The vocabulary, plainly

Teacher (sender)
the AI that already has the skill (e.g. an NLLB translator).
Learner (receiver)
the AI receiving it (e.g. a small Qwen model).
Suite
a test paper. It defines a capability (task/modality/domain/language, e.g. translate/text/translation/as->en = Assamese→English) plus two sets of questions:
  • extraction — questions the teacher is shown (to pull the skill out)
  • heldout — unseen questions the learner is scored on (the real test)
Skill / packet
the thing transferred. A JSON packet of instructions, no weights. This is what you "download" as the trained model.
Gate
the pass/fail decision: PROMOTED (every check passed), REJECTED (named reasons — the system caught something that wouldn't help), or PENDING_HUMAN (high-risk domain like medical / legal / finance → needs your name).
deep-apply
optional: train a real LoRA adapter on the learner's weights from the approved packets, then re-gate (Gate 2). Needs the [deep] install + an in-process HuggingFace model. Lives in the Train tab.
SiltSpring
the compression + certification surface: compress a model to int8 / int4 / int2 and certify each compressed state still passes the skill. Lives in the Compress tab.
For the technically curious — the same idea, in six honest steps. Read this if you want to know exactly what the gate checks and why a REJECTED verdict is the system working.

SILT = Skill Interchange Layer with Trust-gating. A protocol that moves an inspectable skill packet from a teacher AI to a learner AI — but the skill only crosses after it proves itself on cases the teacher never saw. SILT trains no weights by default. The promoted artefact is something you can open and read, not a blob of weights.

A trust layer, not a trainer. Unsloth/PEFT make training fast; SILT decides whether a learned skill may be admitted.
Parity is the streamed admission bar. A streamed parity fail → blocked; standard/zeroforge gate on the all-or-nothing checks. Never a warning, never a fallback.
High-risk never auto-promotes. medical / legal / finance need a named human — not a config knob.
No “% transferred.” Held-out benchmark evidence, not a gauge. No such measurement exists.
  1. 1

    Two models, one skill

    A Sender (teacher) has a capability a Receiver (learner) lacks — translate a language, triage a symptom, fix a bug. The goal is to move that capability, not the teacher's weights. The receiver stays its own model; it gains a skill, not a brain transplant.

  2. 2

    Extract, don’t copy

    SILT probes the sender on a benchmark, then drops everything that would not help: sender_incorrect, receiver_competent, no_delta (relevance), and anything a rule-based safety tripwire catches. What survives is compressed into an inspectable skill packet — JSON with the capability, distilled examples, provenance, and a gate verdict. Raw teacher output is discarded.

  3. 3

    Prove it on held-out data

    Before anything is admitted, the receiver is scored alone vs. receiver + packet on a held-out split the sender never saw. No held-out improvement → no admission. This is why the product shows no “% of knowledge transferred” anywhere: that number does not exist, and showing it would be a lie. What you get instead is a before/after score and a per-case diff.

  4. 4

    The double gate

    Gate 1 judges the packet: relevance, safety, held-out lift, regression on the receiver’s other skills, and high-risk parking. The optional deep-apply stage trains a removable LoRA adapter from only the packets that already passed Gate 1 — then Gate 2 judges the trained adapter again. The gate is all-or-nothing: every check must pass. Gate 2 never trusts the trainer — it has zero trainer-conditional branches; streamed and standard adapters are judged identically.

    For the streamed backend, parity is the admission bar. Parity unverified → the packet records parity_verified=false. Parity fails → DeepApplyBlocked wrapping ParityError, raised before Gate 2. Standard/zeroforge run no parity probe — for them Gate 2's all-or-nothing checks are the bar. Never a warning, never a fallback.

  5. 5

    Honest refusal

    Anything that would degrade, fabricate, or silently serve a worse result raises a typed, named error instead: DeepApplyBlocked, ParityError, StateNotCertifiedError, StaleCertificateError, BudgetError. A 7B model on a CPU-only host is blocked by name — never a fabricated training log. A non-CausalLM architecture is blocked by name — never a silent fallback. The Studio is structurally unable to serve a mock (is_mock is re-checked at build).

  6. 6

    Provenance & rollback

    Every transition is a hash-chained, append-only audit event — tamper-evident, and the single source of truth when something looks wrong. Adapters are removable by construction; v1 never merges LoRA into base weights. Rollback restores the pre-admission state. SiltSpring extends this to compression: a quantized state is certified per (state, skill) against the same held-out suites the gate uses, and a stale certificate (the model changed since certification) refuses to serve.

The one-liner: Trainers make a model able. SILT decides whether the result deserves to exist in the receiver — with held-out proof, a non-bypassable gate, and a hash-chained audit trail. SILT could run Unsloth as the trainer behind its Gate 2.

    Optional deep-apply — streamed & zeroforge

    CLI / test

    The siltstream integration: an optional, separately-installed stage where SILT itself trains a removable LoRA adapter on the receiver, using only packets that already passed Gate 1, then gates the trained adapter again (Gate 2) before admission. Invoked explicitly — never an automatic side effect of a transfer. The core install works without it.

    Install the weights extra
    python -m pip install -e ".[deep]"
    Real-AI opt-in test (asserts the mechanism, not a promotion)
    ASEA_RUN_REAL=1 python -m pytest tests/test_streamed_backend.py -q -k real

    Downloads HuggingFaceTB/SmolLM2-135M, banks it to disk, trains a streamed LoRA on CPU for a few steps, verifies parity (forward + backward), then runs Gate 2. Takes minutes on CPU.

    1 passed (~61s) adapter.backend = "streamed" adapter.parity_verified = true adapter.trainable_param_count = 230400 # real LoRA optimization ran adapter.training_loss = 7.464 # finite (training_loss_finite check passes) gate2.status = "rejected" # evaluator_threshold + benchmark_improvement audit.verify() = {ok: true, entries: ...}
    A REJECTED verdict on a tiny CPU run is the system working — a 3-step streamed LoRA on a 135M English-centric model does not learn Assamese→English. The test asserts the MECHANISM (parity verified, finite loss, intact audit, rollback works), not a promotion.

    Studio surface — Train tab. Deep-apply is now drivable from the Studio Train tab: pick a source transfer job, an in-process HF receiver, the held-out target suite, and a backend (standard / streamed / zeroforge), and the run trains a LoRA on the approved packets then re-runs Gate 2 — streaming a REAL per-step loss curve and parity flag (streamed/standard backends; zeroforge emits phase-level telemetry only and runs no parity probe), and a gate2 verdict as SSE. It can also still be driven from Python / pytest / CLI. The packets it consumes are exactly the ones in your approved store after Step 5.

    The two backends & the parity gate
    backend="streamed"    # layer-streamed backprop LoRA: peft + streaming,
                       #   frozen base in host RAM, decoder layers streamed to
                       #   the GPU one at a time via forward hooks, LoRA params
                       #   resident on device. Low-VRAM, disk-banked. (Soup-spirit,
                       #   Apache-2.0 credited, never claimed as ours.)

backend="zeroforge"   # forward-only zeroth-order (MeZO-spirit): central-difference
                       #   SPSA, no autograd graph, no optimizer moments,
                       #   backward_passes=0. Runs on any forward-only engine.
    For the streamed backend, parity is the admission bar (run before Gate 2).
    • Parity unverified → the packet records parity_verified=false.
    • Parity FAILS → DeepApplyBlocked wrapping ParityError. Never a warning, never a fallback.
    • Gate 2 never trusts the trainer — gate2.py contains zero backend-conditional branches; streamed and standard adapters are judged identically.
    • Adapters are removable by construction; v1 never merges LoRA into base weights. Rollback restores the pre-admission approved-adapter set.
    Honest hardware ladder. No CUDA + a model above the CPU ceiling (~1.5B params) → named DeepApplyBlocked naming the CUDA requirement — never a fabricated training log. A non-CausalLM architecture → DeepApplyBlocked suggesting the standard backend — never a silent fallback. Mock-contaminated dataset → DeepApplyBlocked (defense-in-depth beside Gate 1).
  7. 7

    SiltSpring compression certification

    LIBRARY

    The third SILT surface (beside transfer and deep-apply). A model rests compressed (int2 / int4 — small enough for weak hardware) and expands to higher precision when memory allows. What makes it a trust component rather than a serving trick: per-(state, skill) capability certificates, honest refusal, and staleness-bound certificates.

    Studio surface — Compress tab. SiltSpring is drivable from the Studio Compress tab: pick an in-process HF model, the held-out suites to certify against, the quantization levels (int8 / int4 / int2), a tolerance, and a device. The run measures the full-precision reference loss, then each quantized state's loss, and streams per-state bytes_packed, per-skill degradation, certified/revoked skill sets, and peak VRAM as SSE. The library surface in src/asea/spring/ remains the Python API. Certification reuses SILT's held-out split machinery via suites_from_benchmark — the same held-out cases Gate 2 uses become the suites spring states are certified against.

    Library surface (Python) & named refusals
    from asea.spring import CompressionCertifier, suites_from_benchmark
# suites = suites_from_benchmark(held_out_suites, tokenizer)
# cert = CompressionCertifier(spring_model, audit=audit_log)
# cert.certify(suites)                 # bind certs to the current LoRA fingerprint
# state = cert.choose_state(budget, required_skills=["as_en"])
# cert.serve(state, "as_en")           # raises StateNotCertifiedError / StaleCertificateError
# cert.admit_skill("new_skill")        # invalidates certs → StaleCertificateError until re-certify
    certify(suites)per-(state,skill) vs full-precision reference
    serve(state, skill)refuses a revoked pair
    choose_state(budget, required_skills)honest refusal
    admit_skill(name)invalidates prior certs
    Three named refusals (never silent degraded output):
    • StateNotCertifiedError — a (state, skill) pair is revoked or never certified; serve refuses.
    • StaleCertificateError — a new skill was admitted since certification (the LoRA fingerprint changed); every prior certificate is stale until certify() re-runs. A certificate for yesterday's model must never authorize today's.
    • BudgetError — choose_state(budget, required_skills) cannot find a state that both fits the budget AND is certified for the required skills; it raises rather than serves degraded output.

Differentiation

How SILT differs from Unsloth, PEFT, axolotl & trl

▾

Those are excellent trainer accelerators — they make LoRA fine-tuning faster and lighter. SILT is a different layer: a trust-gated skill-transfer protocol that decides whether a learned skill may be admitted to a receiver. They answer different questions, so they are complementary, not competitors — SILT could run Unsloth as the trainer behind its Gate 2.

SiltSpring compression certification

Measures the full-precision reference loss on the held-out suites, then each quantized state's loss, and marks a state certified for a skill when degradation ≤ tolerance (directional — only a WORSE loss revokes). Requires the [deep] extra (pip install -e ".[deep]"); without it the run fails with a typed error before any weights load. A 7B model needs the ~14 GB fp16 reference resident and will not fit an 8 GB GPU; pick a model that fits (e.g. SmolLM2-360M / Qwen2.5-0.5B) or use CPU. An OOM load fails with a typed error — never a silent pass. Per-state bytes_packed, per-skill degradation, certified/revoked skill sets, and peak VRAM are REAL, streamed from the vendor certify_hf_states. If a state's loss is non-finite (a degenerate quantization on an out-of-distribution model, e.g. int2 on a tiny model) its degradation cannot be computed and the state is marked UNMEASURED, not certified — a non-finite loss is never rounded to a fake number or silently passed.
