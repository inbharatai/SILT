📦
01 · TRANSFER

Represent a narrow skill

An inspectable Skill Packet — rules, glossaries, exemplars, structured instructions. Teacher weights are never copied.

Full discipline

The default L3 path creates capability/modality-specific packets. Extraction includes gap measurement, relevance filtering and safety tripwires. Cross-family transfer assumes no shared vocabulary.

🧪
02 · PROVE

Evaluate beyond extraction

Held-out A/B: baseline vs candidate, regression sweep, declared provenance. Verdict: PROMOTED, REJECTED, or PENDING_HUMAN only when approval metadata is the missing piece.

Full discipline

Held-out cases are separated from the extraction workflow — not guaranteed unseen in pretraining. High-risk medical/legal/finance domains require caller-supplied approval metadata; the approver name is not verified human review. A gate can only measure what its tests and policies cover.

🗜️
03 · ADAPT

Fit the deployment constraint

Optional removable-LoRA deep-apply, re-gated by an independent Gate 2. SiltSpring measures quantized-state loss. A separate path rebuilds smaller specialists from source weights.

Full discipline

Deep-apply trains LoRA only from Gate-1-approved packets; adapters stay removable, never merged into base weights. Training completion alone never admits an adapter. SiltSpring compares next-token loss on operator-provided suites against a resident reference — held-out-only filtering is not automatic, and loss thresholds do not prove whole-device fit. Construction complete (BUILT_UNCERTIFIED) is not quality passed. Native Windows, macOS/MPS, ROCm, multi-GPU and offload are unsupported; CUDA staging is not out-of-core execution.

The full boundary text — every caveat, nothing hidden

Evidence controls have boundaries. Core safety checks are rule-based tripwires; provenance depends on trusted declarations and regression coverage on supplied suites. Hash-chained audit records, runner telemetry, local HMAC reports and retained traces are different evidence types — not external authentication. Mock fixtures demonstrate mechanics; recorded model runs support bounded results; neither establishes broader capability.

SiltSpring: int8/int4/int2 reports compare next-token loss on operator-provided suites against a resident reference; neither decoder-layer bytes nor loss thresholds prove whole-device fit or task quality. Real HF and toy Spring reject invalid/non-finite loss evidence. Streamer exit restores banked parameters and persistent buffers — not live LoRA or failed-entry states. Toy state-selection is not the real Studio report path.

Deep-apply + Gate 2: packet-derived LoRA training then a second benchmark; Gate 2 inherits source-packet safety scores and is not a comprehensive trained-output safety audit.

SiltStream: layer-streamed LoRA with disk-backed frozen decoder layers; sampled pre-training forward logits prove parity, not identical gradients or learned weights; full resident loading/parity is still required first.

ZeroForge: forward-only SPSA-style LoRA updates — zero backward passes still means multiple forward passes per update and real memory costs; not free compute or a GPU-independence advantage.

Asymmetric SPRT (evaluator API): stops sufficiently negative candidate evaluations early; never early-promotes; off by default; nominal error settings depend on test assumptions.

Compiler (experimental): native Switch pruning physically removes experts/router rows and exports weights; certification is a separate narrow seq2seq-text operation; pruning is not admission; repair-training unsupported; not an arbitrary-MoE compiler.

Reconstruction & recovery: Qwen2 MLP-channel slicing and Switch→dense-T5 are family-specific transformations requiring explicit local source weights and calibration; RECONSTRUCTED_UNVALIDATED establishes nothing about retained quality. Factor-preserving bundles need complete base + factors + tokenizer + matching SILT/PEFT runtime — not plain HF-root or GGUF loading. The recorded BF16 merge failed and was preserved, not relaxed.

Portable artifacts: dependency-inclusive Compose export and bounded import validate inventories and rebind paths; imports stay unadmitted until fresh local evaluation; relocation is not clean-machine certification. Legacy packet export produces unexecuted job recipes, not checkpoints.

Compose & speech bridges: typed linear chains of 1–16 local nodes (not arbitrary branching or latent fusion); Whisper/Vits/MMS are bounded CPU float32 paths; audio-output admission stays blocked — waveform/listening packets are pending-human, not intelligibility or MOS certificates. Matched SmolVLM/Idefics3 vision→text is an implemented bridge, not broad OCR certification. Model licensing constrains use.

Governance & observability: validation registries, consumed final reservations, external function-IO grading, generation/oracle traces and resource probes expose what ran and failed. Linux process_as limits virtual address space, not aggregate RSS; unsupported Windows/cgroup execution fails closed.

Capability-build research layer

Footprint a teacher's capability. Intervene causally. Search for the minimum.

A separate research CLI (silt-capability) asks one question under an operator-written spec: what is the minimum artifact that reproduces a narrow capability in a much smaller student — proven on untouched held-out tests, without regressing controls? Read the guide →

👣
FOOTPRINT

Teacher footprinting

Two never-mixed evidence classes: behavioural (per-run remote consent) or instrumented open weights via an isolated worker. A footprint names components associated with a capability — routing usage is never called causal importance.

🎭
INTERVENE

Causal intervention

Temporarily mask one component, measure target vs control drops, restore, verify weights byte-identical. Unrestorable = never causal evidence. Small hosts get a typed BLOCKED_RESOURCE — honest, not a skip.

📉
REDUCE

Teach, then reduce

Fresh five-split datasets with leakage guards; no measured gap → no distillation. Every candidate and failure recorded. A smaller parameter count is not evidence — only held-out scores count.

What the executed pilot showed — and did not

One judged pilot ran the full chain against an operator-selected cloud teacher: a frozen five-split case set (the final split has never been opened), 16 consented teacher traces, and the same host oracle grading teacher and a much smaller local student on identical checks — 0.8649 vs 0.4595 target-check pass rate, a measurement of that case set only, never a model-quality claim. The 6 judged training traces became KD pairs, which trained a real LoRA adapter through the production trainer; an independent oracle A/B then judged base vs adapter and returned a mixed verdict: untouched held-out checks improved 0.8889→1.0 with no control regression, but the aggregate target rate regressed 0.8108→0.7143 — recorded as a regression, because with 6 training pairs this is mechanism-scale evidence and the honest numbers are the product. Nothing was admitted, activated or certified: production admission stays with the existing Deep-apply/Gate 2 path, and minimum-capability search remains unexecuted — its CLI refuses honestly rather than emit placeholders.

Honest scope

What SILT claims — and what it does not.

What exists in the repository

  • ✓ Inspectable L3 Skill Packets and held-out A/B evaluation.
  • ✓ All-or-nothing admission with regression suites, safety tripwires, provenance, rollback and audit.
  • ✓ Mandatory approval metadata for declared high-risk domains (not verified human identity).
  • ✓ Optional removable-LoRA deep-apply + independent Gate 2; SiltStream, ZeroForge, SiltSpring, opt-in SPRT.
  • ✓ Local diagnostics: Capability Diff, skill-layer Unlearning.
  • ✓ Experimental reconstruction/recovery/export, composition and media bridges, compiler, governance, portability.
  • ✓ Studio, CLI, examples, tests and recorded real-run findings — including every rejection.

Full activation catalog — completed models remain uncertified.

What SILT does not claim

  • ✗ Universal arbitrary capability copying between any two models.
  • ✗ Complete transfer of a teacher's knowledge or internal weights.
  • ✗ AGI or unrestricted autonomous self-improvement.
  • ✗ Frontier-model reconstruction, arbitrary billion-parameter models on 4 GB, or universal GPU/Windows validation.
  • ✗ A fabricated "percentage of knowledge transferred" — SILT reports benchmark deltas and gate verdicts.
  • ✗ A universal safety guarantee: a gate measures only what its tests and policies cover.
  • ✗ Patent novelty for standard LoRA, or coverage of the reconstruction/recovery mechanisms by the existing provisional.
SILT Studio

Use Studio locally. Choose where inference runs.

This page and public /studio/ are static setup pages — not a hosted engine. Start the local service, then open 127.0.0.1:8377. Privacy follows your endpoint choice: local orchestration does not make cloud-backed inference local.

  1. Install the required extras and compatible models.
  2. Choose local or remote model endpoints — explicitly, every time.
  3. Start Studio and open 127.0.0.1:8377.
  4. Optional workbench: set SILT_ENABLE_EXPERIMENTAL=1 before startup, then open /experimental. Off by default; restart after changing an off-start.
