The model you want may not know the skill you need.

A general model can be useful yet weak at a language, domain workflow, coding pattern, pronunciation rule set or other measurable capability. Another AI may already perform that narrow task better.

SILT separates three questions: can we represent and transfer the capability, did the receiver actually improve, and can the resulting system operate in a constrained hardware state without silently losing the skill?

The SILT thesis

Transfer → prove → adapt.

The trust gate is the enforcement layer. It exists so a transferred packet, a trained adapter or a compressed state cannot simply declare success. Each stage has to be evaluated against evidence appropriate to that stage.

🔁

Inspectable Skill Transfer

The default path represents a narrow capability as an inspectable packet of rules, glossary entries, exemplars or other structured skill material. It does not copy the teacher's weights.

default L3 path · removable · re-testable
🛡️

Held-Out Proof + Gate 1

The receiver is evaluated before and after the candidate skill on held-out cases, with regression, provenance, rollback and safety checks. High-risk medical, legal and finance domains require a named human.

measured admission · named rejection reasons
🔥

Optional Deep-Apply

Already-approved packets can be used to train a removable LoRA adapter. The resulting adapter is evaluated again by Gate 2 instead of being trusted merely because the training loop completed.

optional weights mode · second independent verdict
⚙️

Hardware-Aware Adaptation

SiltStream and ZeroForge explore training paths for constrained compute. Their usefulness is hardware- and model-dependent, so SILT records and tests the mechanism rather than claiming every large model will fit every small machine.

constrained-compute R&D · explicit limits
🌀

Skill-Aware Compression

SiltSpring evaluates compressed int8 / int4 / int2 states per skill. Certification is tied to the specific model state and skill; an uncertified or stale state can be refused rather than silently served.

per-state · per-skill certification
📜

Audit + Rollback

State transitions are written to a hash-chained local audit log, and SILT-managed approvals use snapshots and rollback metadata so the approved skill set can be restored.

tamper-evident locally · reversible SILT-managed state

SILT does not display a "% of knowledge transferred" gauge. The repository reports benchmark evidence and named verdicts instead. Hardware-specific claims should be read from the corresponding recorded run artifacts, not inferred from a feature name.

Different layer, different job

Training creates a candidate capability. SILT asks whether the receiver should keep it.

SILT is designed to complement training frameworks rather than replace them. Its distinctive role is the transfer/evaluation/admission discipline around the capability and the hardware state in which that capability may be used.
